## Key findings (read these first)

1. **FA Interfaces has no stored projection and its GET writes.** The schedule is re-derived from JSON readings on every request (models.py:2459-2475; service.py:797-843); each GET also stat-walks the whole IFC folder tree (evidence.py:166-185), creates the project row (service.py:181-187) and, through `Floors()` -> `building_floors.resolve_aliases`, inserts or rewrites `project_floor_aliases`, which the handler then commits (fa_interfaces.py:62-67; exports and review-cases do the same at 433, 452, 476). The matrix, detect rules and floor rules carry no version in the evidence digest (evidence.py:216-224), so a code change silently re-prices every project's published schedule.
2. **IFC quantities are not stored; they are derived on each read from a company-wide, unversioned symbol library.** `resolved_drawing` matches stored symbol groups against every IfcSymbol on every GET (resolve.py:186-285), so one engineer's verify, unverify (which deletes any symbol, engineer-confirmed or not: ifc_boq.py:247-265) or a device-type edit re-counts every project; AI answers accepted at >= 0.97 count as verified exact matches with no engineer step (resolve.py:132-133, config.py:235); admin reprocess stores machine carry-overs with engineer authority and no reviewer (reprocess.py:60-80).
3. **Overrides are weaker than the CSV says.** FWS.edits has four writers (floor schedule, amplifier and power routers), is keyed by description (collisions), is not re-applied by a workbook upload, and 'clear' is undone by the next GET while a workbook sits in 03- Design (floor_schedule.py:87-137, 160-235, 511-523; floor_schedule service:604). FA decisions are keyed by file path + sheet + rounded label coordinates with no compare-and-set (fa_interfaces.py:298-369; service.py:1306-1312), and the legacy scan can auto-publish over an engineer's publication and record the scanning user as publisher (service.py:466-474). The engineer cannot edit the floor registry at all (building_floors.py:276-287).
