## 2. Reading guide

### Columns

The CSV has the same 22 columns, in the same order, as the accepted CSV (`field_id`, `module`, `consumer_location`, `field_name`, `semantics`, `data_type`, `cardinality`, `current_producer`, `current_source`, `current_table_model_column`, `current_service_function`, `current_extraction_logic`, `current_ai_dependency`, `current_derivation`, `target_producer`, `target_source_of_truth`, `consumers`, `freshness_dependencies`, `engineer_override_rules`, `missing_unknown_behavior`, `evidence_refs`, `status`). Every cell is double-quoted, the file is UTF-8 with LF line endings.

- The `current_*` columns state what the code does at HEAD. The `target_*` columns are proposals and are marked PROPOSED by the surveyors where they come from the roadmap. Surveys S2 and S3 did not decide targets: S2 writes `UNKNOWN: not decided in this refresh` and S3 writes `UNKNOWN (roadmap)` in the target cells of the rows where no target was given. The scribe copied them as written.
- Storage notation is the accepted one: `Model.column` is a mapped column; `json:table.column $.path` is a key inside a JSON column; `DERIVED` means computed on read and not stored.
- A pipe inside a surveyor cell was written `\|` in the survey tables. In the CSV it is a plain `|`.
