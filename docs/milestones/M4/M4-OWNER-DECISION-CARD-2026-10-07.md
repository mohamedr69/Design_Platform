## 2. Items identified separately

The owner may be the reviewer; the orchestrator and its agents may not.

**2. The remaining OCR residual (M4 closure item 1, residual a).** Fixed on the branch: a scan left unread for want of OCR is a partial reading, and a short-text scan that produced a record is partial too (verifier-specified correction; gate set 105 passed). Still open for the owner: a text page of 80 or more characters that carries an image stamp on a candidate page still reads as *complete* when Tesseract is absent, although the same page is *partial* when OCR is present and fails; the code's own example is a ticked "Approved as Noted (B)" beside a pasted "(C) Revise & Resubmit" stamp, where without Tesseract the tick decides. Flagging such pages would make every candidate drawing with a logo of 14 pt or more permanently partial on a PC without Tesseract. Recommended: do not flag by image size; record instead a deployment requirement that every processing machine has Tesseract (the supported Windows deployment does), make the processing status show whether OCR was available for each run, and treat a page read without OCR as *complete without OCR* in the coverage record so the limitation is visible, not silent. Alternative: flag by image size (noise on every logo). This is an owner decision because it trades a visible limitation against permanent partial readings.

**3. The unresolved part-catalogue question.** `test_proposed_materials::test_the_part_catalogue_knows_every_number_on_file_for_a_brand_and_completes_it` fails on every recorded run: `part_catalog.catalog` never reads the datasheet library although its docstring names the library as the first source (`get_libraries` imported and never called; `_from_filename` has no caller), so `GET /parts/search` never offers parts known only from datasheet file names; a second divergence is a seeded number (`CTR400CGL2KS-M`) the test does not expect. Question for the owner: was the file-name source dropped on purpose? Recommended: treat it as a code defect for M4 and restore the file-name source from the library index built at startup and on the throttled rescan, never by scanning the library inside the GET (M10 rule), and align the test's seeded-number expectation; if the source was dropped on purpose, retire the test and the docstring instead. Either way it is the one remaining test failure on the supported platform.
